# Changelog

## [Unreleased]

### Fixed
- Nested control results advance the projection cursor instead of being re-read on every status render, and are reclaimed once no waiter can still match them, so the nested event sink no longer grows without bound.
- A workflow child aborted during setup is retried once under a delegated one-use child permit, instead of failing with a misleading permit error; the retry is host-initiated, granted for that child only, and bounded to one spawn so a delegated workflow still cannot spawn unbounded children. A launch refused for a mismatched projection no longer consumes the allowance.

- Schedule recurrence admission completes before claiming work. An unrepresentable future recurrence is diagnosed without blocking an already-known child completion; failed terminal publication retains observer ownership and reports both failures. A still-current armed occurrence with `catchUp: "none"` tolerates late timer delivery, while restoration and explicit due scans still skip missed work.
- Async workflow startup validates child-summary identifiers, persists initial status, and prepares all required receipt projections before marking capacity started or scheduling its Worker. Prelaunch failures dispose both persistence writers and pending retries; known-unstarted owned status and active/tool-call/terminal indexes are synchronized even with unlimited capacity or a write that committed before throwing. Cleanup I/O failures are reported alongside the original error, while started or uncertain ownership and post-admission mission warnings keep their existing semantics.
- Schedule activation checks the captured project's current trust decision on restore, actions, timers, and immediately before launch. Inert inspection and pause/delete remain available without trust, and already-launched work keeps its ownership.
- Persisted schedule triggers validate positive, consistent intervals and valid dates; recurrence advancement is bounded and checks overflow. Invalid records are reported individually during restoration.
- Detached workflow child errors retain their whitelisted scalar classification across the sandbox boundary, so async status, results, and receipts correctly record a pause. Automatic JavaScript continuation remains unsupported.
- Prompt frontmatter parsing accepts an empty or comment-only block as an empty mapping again, an empty block no longer leaks its `---` delimiters into the prompt body, and one malformed prompt file no longer disables every prompt workflow in the directory.
- A corrupt model-exclusions store no longer blocks persistence of new exclusions; the store is rewritten from the in-memory state.
- Fixed timeouts above 2147483647ms firing almost immediately, a failed terminal status write overwriting a successful async workflow result and crashing the host, interrupts never escalating to SIGKILL, quadratic workflow trace journals, and git usage text in timeout recovery summaries.
- Fixed Codex exec runs failing on retried `error` events, agents with `turnBudget`/`toolBudget` frontmatter failing to load, unknown frontmatter fields being corrupted on update, children launching without `--model` when every candidate was excluded, worktree patches over 1MiB being lost, nested artifact directories never being cleaned, non-atomic settings writes, and `shortenPath` matching home-directory prefixes.
- Fixed resumed async runs failing after 10s while the runner started with a cold transform cache (the startup handshake no longer blocks the event loop), and a dead LSP server being reported as a timeout after the full deadline.
- Fixed `subagent_wait` not returning for a pending `contact_supervisor` request (progress updates still do not end the wait), and late supervisor replies being lost: requests stay answerable while the subagent runs and late replies arrive as steering messages.
- Fixed `settings.json` writes replacing a symlinked file with a regular file and resetting its mode, and taking a lock the coding agent could not reclaim after a crash; settings writes now follow links, keep the mode, and use the coding agent's lock protocol.
- Fixed a language server that died after publishing some diagnostics losing them.
